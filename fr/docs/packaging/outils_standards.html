20  Les outils de développement

20.1 Isoler les environnements : venv

Afin de travailler dans un environnement stabilisé sans ambiguïté sur l’interpréteur utilisé et avec des dépendances maitrisées, Python propose d’isoler la configuration de l’environnement avec les environnements virtuels.

20.2 Création d’un environnement virtuel

python -m venv .venv
  • python : utiliser la version explicite de la version qui sera la version du venv (par exemple python3.14).
  • -m venv : exécution de venv.
  • .venv : chemin du répertoire de création du venv, ici .venv dans le répertoire courant.

Vous pouvez créer le répertoire contenant le venv n’importe où. Le créer dans le répertoire du projet permet d’avoir un venv dédié au projet et le nom .venv est convenu pour utiliser la propriété du fichier caché sous les environnements POSIX.

20.3 Usage et activation de l’environnement virtuel

Précisions : dans l’arborescence de l’environnement virtuel, les exécutables sont dans un sous-répertoire dépendant du système : bin sous Linux et MacOs, Scripts sous Windows.

Les environnements virtuels sont destinés à être utilisés dans une invite de commande et configureront le process. Ils sont intégrés dans les principaux IDEs mais leur usage n’est pas couvert ici.

20.3.1 Activation d’un environnement virtuel

Voir la documentation

Sous Linux ou MacOs

source .venv/bin/activate

Sous windows, selon que l’on soit sous le PowerShell ou le cmd :

.venv\Scripts\Activate.ps1
.venv\Scripts\activate.bat

Suite à cette activation, vous utiliser python et pip de l’environnement virtuel. ### Utilisation directe des exécutables

Pour un usage simple, vous pouvez utiliser directement les exécutables de l’environnement virtuel (pour Linux ou MacOs) :

.venv/bin/pip list
.venv/bin/python

20.4 Gérer les dépendances : pip

pip est l’outil standard de gestion des dépendances. Si vous travaillez avec un environnement virtuel (conseillé), vous devez l’activer auparavant.

Les instructions principales sont :

20.4.1 Lister les packages installés

pip list

20.4.2 Créer une référence des dépendances

La commande pip freeze affiche les dépendances de l’environnement courant dans le terminal. Elle est utilisée pour créer le fichier informant des besoins de ce projet :

pip freeze > requirements.txt

20.4.3 Installer des dépendances

1pip install my_package
2pip install -r requirements.txt
1
Installe le package en argument
2
Utiliser le fichier requirements.txt pour installer l’ensemble des dépendances nécessaires au projet.

pip permet de passer par un proxy, vous devez alors connaitre l’adresse du proxy et utiliser une syntaxe du type :

python -m pip install --proxy user:pass@proxy.server:port my_package

20.5 uv, Gestionnaire de projet Python moderne

uv est un outil écrit en Rust, développé par Astral (auteurs de Ruff).
Il remplace en un seul binaire : pip, pip-tools, virtualenv, pyenv, pipx et partiellement poetry.

L’installation ne sera pas abordée ici car spécifique des systèmes, voir la documentation

20.6 Créer un projet

uv init mon_projet
cd mon_projet

Structure générée :

mon_projet/
├── .python-version
├── pyproject.toml
├── uv.lock
├── README.md
└── main.py
1
Version Python épinglée
2
Configuration du projet
3
lockfile généré automatiquement

Pour uv, la référence des dépendances est le uv.lock. Ce fichier est à ajouter au référentiel. il décrit la version exacte des dépendances utilisés et sera utilisé pour le partage du projet.

20.6.1 Installer des dépendances

20.6.1.1 Dépendances de production

uv add requests
uv add "httpx>=0.27"
uv add fastapi uvicorn

uv met à jour le pyproject.toml :

[project]
dependencies = [
    "httpx>=0.27",
    "fastapi>=0.110",
    "uvicorn>=0.29",
]

20.6.1.2 Dépendances de développement

uv add --dev pytest
uv add --dev ruff mypy
uv add --dev "pytest-cov>=5.0"

uv crée la section dans le pyproject.toml :

[dependency-groups]
dev = [
    "pytest>=8.0",
    "ruff>=0.4",
    "mypy>=1.9",
    "pytest-cov>=5.0",
]

20.6.1.3 Supprimer une dépendance

uv remove requests

20.6.2 Synchroniser l’environnement

Lors de la récupération d’un projet, on utiliser le fichier uv.lock pour configurer son environnement :

uv sync           
uv sync --no-dev

uv sync crée ou met à jour .venv/. L’option --no-dev permet de n’installer que les dépendances de prod.

20.6.3 Lancer des commandes

Pas besoin d’activer le virtualenv :

uv run python main.py
uv run pytest
uv run ruff check .
uv run mypy src/

uv run détecte automatiquement le .venv/ du projet.

20.6.4 Le fichier uv.lock

uv.lock est généré automatiquement. Il contient les versions exactes de toutes les dépendances (directes et transitives), garantissant la reproductibilité sur toutes les machines.

uv lock

À committer dans Git. Ne pas l’éditer manuellement.

20.6.5 Compatibilité

uv génère un pyproject.toml standard (PEP 621) : les projets restent compatibles avec pip et les autres outils de l’écosystème Python.

Si vous souhaitez revenir vers l’usage de pip classique, vous pouvez exporter les requirements :

# Exporter vers requirements.txt (CI, Docker…)
uv export --format requirements-txt > requirements.txt
uv export --format requirements-txt --no-dev > requirements.txt

20.6.6 Pour le packaging

Vous pouvez utiliser uv pour le packaging. Il faut indiquer le build-system dans le pyproject.toml :

[build-system]
requires = ["uv_build >= 0.11.7, <0.12.0"]
build-backend = "uv_build"
